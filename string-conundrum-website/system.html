The system

String Conundrum is a React single-page application backed by a Flask API and PostgreSQL, deployed on a UCT Computer Science server. The browser displays the interface, and the server runs, traces and grades code.

0Learning path

Eight modules, five stages each

Every module has the same five stages, from explanation to assessment. A score of at least 80% in a module's exam unlocks the next module. A setting allows learners to open any module, and after a failed exam the learner is directed to practice on the concepts they missed.

  1. 0LearnShort explanations with code, callouts, tables and key points.
  2. 1ExamplesWorked examples stepped character by character.
  3. 2VisualiseThe module's operations play in the visualiser automatically.
  4. 3PracticeGenerated questions with misconception-linked feedback.
  5. 4ExamA paper drawn from a 276-question bank; 80% unlocks the next module.

Each module is stored as a content file and displayed by shared components according to the type of each block. New modules, exercise types and languages can be added as data without changing the rendering code. Lecturers can also create, reorder, publish and hide modules and exercises from their dashboard.

1Visualise

The String Visualiser

Participants and reviewers rated the visualiser highest of all the features. It is available as a standalone page, which guests can use, and in the Visualise stage of every module.

  • Six modes: slicing, index access, for loops, while loops, if statements and string methods.
  • Positive and negative indices. Positive and negative indices sit above and below the characters, and slice bounds are labelled start (inclusive) and stop (exclusive).
  • Playback. Play, pause and speed controls, with spoken narration that finishes each sentence before the next step.
  • Tested against CPython. The engine was tested against 132 slice and 60 index expressions evaluated by CPython. If an expression cannot be evaluated, an error is shown instead of an empty selection.
  • isiXhosa narration. Major browsers do not include an isiXhosa voice, so choosing isiXhosa narration shows a message that explains this.

2Experiment

Code Space

An editor and output panel for running Python code, separate from the modules and available to guests. It shows output and errors but does not give marks.

  • Server-side sandbox. Code runs in a fresh subprocess with a five-second wall-clock limit, restricted built-ins that remove imports, file access and dynamic execution, and a 64 MB memory cap on POSIX hosts such as the Linux server.
  • Step-through tracing. An AST-based tracer replays the program statement by statement, up to 200 steps, with the characters each step touches highlighted.
  • Supported code. The visualiser pane states which code it can trace, so unsupported code is not shown as an empty result.
  • isiXhosa keywords. A transpile control rewrites the editor's keywords into isiXhosa, with a banner confirming the switch.

3Practise

Practice, exams and misconception-linked feedback

  • Four question types: multiple choice, select-all, short answer and code writing. Code-writing answers are run as programs, so any correct solution earns credit.
  • Generated questions. Each module generates questions from concept templates combined with different strings, question types, answer formats and difficulty levels, so learners can keep practising without seeing the same questions.
  • Misconception feedback. Distractors are linked to named misconceptions where possible, and a worked-example panel shows the rule with the same character-cell highlighting as the visualiser.
  • Adaptive practice. The browser counts the misconceptions a learner has shown, and later questions are more likely to target them while still covering other concepts.
  • Server-side grading. Each question carries a signed token. The server recomputes the expected answer when grading and rejects altered submissions. The answer key is never sent to the browser.

4Localise

English and isiXhosa

Lessons, prompts, hints and feedback are available in isiXhosa, and learners can also write Python keywords in isiXhosa. The code that the server runs is always standard Python.

Teaching content

Translated before deployment

All eight modules were translated with the NLLB-200 model and the results committed, so no translation model runs on any request. Code fragments inside prose are masked before translation, and a check rejects any translation that alters them. Translations are applied field by field, and any untranslated field is shown in English.

5Go further

Challenges, leaderboard and the lecturer dashboard

Challenges

18 coding problems

Seven easy, five medium and six hard problems, each with a hint, a worked solution and test cases. A submission runs against every stored test and counts only if all of them pass.

Leaderboard

Optional participation

Learners choose whether to appear and under what name, or can appear anonymously. Rankings are calculated from recorded completions.

Lecturer dashboard

Progress monitoring

Overview, Students, Marks, Analytics, Modules and Content pages, available to lecturers only. Figures come from the server, and values that were not recorded are shown as missing rather than as zero.

6Architecture

System architecture

Design decisions

Grading on the server. Grading, code execution and lecturer analytics run on the server. Answer keys are not sent to the browser, and there is one grading implementation.

Only Python on the server. isiXhosa keywords are converted to Python in the browser, so the sandbox and tracer only process standard Python.

PostgreSQL instead of Firestore. The proposal planned to use Firestore. It was replaced by PostgreSQL because progress, completions and leaderboards needed aggregation and uniqueness constraints. Firebase is still used for authentication.

A fixed API contract. The interface between the front end and the back end was agreed before parallel development began, and it was kept stable while both sides changed in response to evaluation.

7Request lifecycle

What happens when you press Run

  1. 0

    Transpile, if needed

    If the learner wrote isiXhosa keywords, the browser converts them to Python first. Nothing else is translated.

  2. 1

    Two requests in parallel

    POST /api/execute runs the program and POST /api/debug asks for its trace, issued together.

  3. 2

    Run in the sandbox

    A fresh subprocess with restricted built-ins, a five-second wall clock and a 64 MB address-space limit. A program that runs too long is stopped and reported as a timeout, without blocking the Flask server.

  4. 3

    Trace the program

    The tracer parses the code once with Python's ast module and walks it statement by statement, recording the line, event, variables and the exact character indices each step touches.

  5. 4

    Explain a failure

    If execution failed and the learner works in isiXhosa, the matching error template is filled in, with details such as the line number.

  6. 5

    Render

    The browser shows each step as highlighted character cells with narration, and displays output and errors in different styles.

The tools used in the project's code, build and deployment, grouped into five layers.

A React single-page application. It displays content and sends answers to the server for grading.

  • Vite 5Development server and production build.
  • JavaScript ES modulesThe visualiser engine, the isiXhosa transpiler and the request layer.
  • CSS ModulesScoped styles on shared design tokens, with light and dark themes.
  • Lucide 1.xInterface icons, including the open-book logo.
  • Web Speech APISpoken narration in the visualiser.

On the server

A Flask API that runs, traces and grades code.

  • PythonThe back-end language and the language being taught. The tracer uses its ast module.
  • Flask 3.0REST endpoints for execution, tracing, practice, grading and progress.
  • GunicornProduction WSGI server, running the API with four workers.
  • pytest 8.3274 back-end tests, run in continuous integration.
2

Data and identity

User data in PostgreSQL; sign-in handled by Firebase.

  • PostgreSQL 18Users, progress, attempts, challenges and lecturer content, reached through psycopg2.
  • Firebase AuthenticationSign-in in the browser with the Firebase SDK 12. ID tokens are verified on the server.
