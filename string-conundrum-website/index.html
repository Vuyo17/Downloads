String Conundrum

# Why did my code do that?

A web-based tutor that helps novice programmers build an accurate mental model of Python strings. It shows what an operation does to each character, answers a wrong answer with the misconception behind it, and teaches in English and isiXhosa.

1The problem

Strings look simple. The mental models behind them often are not.

Strings appear in every introductory programming course and almost every exam, yet indexing from zero, exclusive slice bounds and immutability are invisible in the source code. A student with the wrong model can write code that runs, prints something plausible and never reveals the misunderstanding.

  • 29,627students made incorrect string-equality comparisons in 37 million novice compilation events; the median fix took over 1,000 seconds. Altadmri & Brown, 2015
  • 49%of students completed a string-manipulation task after a full semester, and only 6% used string methods they had been taught a week before. Izu & Weerasinghe, 2020
  • 0 of 7online coding tutorial systems in a systematic review addressed string-specific difficulties. Alasmari et al., 2023

3Project aims

What we set out to do, and how it turned out

The objective, in the words of the project poster: an interactive web-based platform that helps novice programmers learn Python strings through visualisation, practice, misconception-targeted feedback and English/isiXhosa learning support.

  • Visualise
  • Feedback
  • Localise

The proposal set five aims. Four were met in full. The fifth was met for usability, but the controlled learning study it also called for was not completed, so we make no claim about learning gains.

Read the project proposal (PDF)

  1. 1

    A visual representation of strings

    Show strings as indexed character sequences whose characters light up as operations run.

    A six-mode visualiser with positive and negative indices shown together, checked against 192 expressions evaluated by CPython.

    Achieved
  2. 2

    A code input and transformation pipeline

    Accept Python string code, evaluate it and turn the result into the visual representation.

    Sandboxed execution plus an AST-based tracer whose step-by-step JSON drives Code Space's visualisation; all 257 traced test programs matched CPython.

    Achieved
  3. 3

    A structured exercise system

    Present string concepts in a principled progression, using questions built on real Python.

    Eight modules with an 80% exam gate, a 276-question exam bank and procedurally generated practice for every module.

    Achieved
  4. 4

    Misconception-targeted feedback

    Identify the misconception behind a wrong answer and explain it in plain language.

    A 24-entry misconception catalogue drives distractors and feedback; 11 of 13 students in the first-year cycle agreed the feedback helped them correct misconceptions.

    Achieved
  5. 5

    Evaluation with first-year students

    Usability testing, and a comparative pre- and post-test learning study.

    Three usability cycles with 35 students (pooled SUS 80.8). The controlled pre/post study remains future work.

    Partly achieved
  6. +

    Beyond the proposal

    isiXhosa localisation, an optional stretch goal in the proposal, shipped in full. So did spoken narration, coding challenges and a lecturer dashboard, none of which the proposal included.

    Extra scope

4Key findings

What the evaluation showed

Thirty-five students in three cycles, three peer developers, four HCI reviewers, a supervisor acceptance walkthrough and five technical experiments with criteria fixed in advance.

5 of 13

The visualiser was the standout

All 13 students in the first-year cycle agreed that highlighted indices and slices helped them reason. The visualiser was chosen most often as the single most helpful feature, and all three peer developers singled it out unprompted.

7 of 35

The target misconception is real, here

Participants in every cohort predicted that word[0] = "J" turns “Python” into “Jython”. The belief did not fade with seniority, which is local evidence for the premise the whole design rests on.

79.8

Usable by the intended audience

Usability held up when the audience moved from experienced students to first-years: the first-year cycle scored 79.8 overall and 82.5 among the ten self-identified first-years.

1,600

Two kinds of evaluation found one defect

Students said they did not always trust their marks. A 1,600-question automated sweep, run in response, located a grading-presentation defect that was then fixed.
