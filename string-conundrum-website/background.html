1Background

Why strings are a conundrum

Strings appear in every introductory course and nearly every exam, yet much of their behaviour, from zero-based indexing to exclusive slice bounds and immutability, is invisible in the source code. This page sets out the evidence, the theory and the gap String Conundrum was designed to fill.

0The evidence

Strings are hard, and the difficulty persists

Studies of different languages, institutions and kinds of data point the same way: string errors are common, slow to fix and resistant to ordinary instruction.

1 in 3students fails or withdraws from introductory programming, a rate that has barely moved in decades. Watson & Li, 2014
29,627students made incorrect string-equality comparisons across 37 million compilation events; the median fix took more than 1,000 seconds. Altadmri & Brown, 2015
49%of 338 students completed a string-manipulation task after a semester, and only 6% used string methods taught a week earlier. Izu & Weerasinghe, 2020
100%of runtime errors in one cohort's first Java assignment were string-formatting errors, in a single-institution case study. Hughes et al., 2010
10.85concept components were needed, on average, to answer one CS1 exam question, and strings appeared in every exam studied. Luxton-Reilly & Petersen, 2017
UCTMarks in practical assessments and assignments drop when string concepts are introduced. This was the local motivation for the project. Project proposal

These sources measure different things, from compiler errors to task completion and exam structure, but they share a blind spot. Compilation logs only record code that fails to compile, so conceptually wrong code that runs and prints the wrong answer goes uncounted. That silent failure is exactly what a string misconception produces.

1Theory

Why strings resist instruction

Computing-education research explains the persistence with a few complementary ideas. None of them prescribes a tool, but together they say what a tool has to do.

Notional machines

The wrong model feels right

Novices reason with a simplified model of how the computer runs their code. When that model diverges from what the language actually does, errors persist however often the correct syntax is shown. Sorva, 2013

Silent errors

Nothing tells the student

Conceptual errors are harder to fix than syntax errors because they give no immediate, visible feedback. Most string operations run without complaint, even when the student's prediction was wrong. Qian & Lehman, 2017

Competing models

Arrays or objects?

In one study 53% of participants treated strings as character arrays and 32% as objects with methods. The two models predict different behaviour for the same code. Izu & Weerasinghe, 2020

Superbugs

The computer as mind-reader

Learners often behave as though the computer understands their intent. With strings, that becomes an expectation that a value updates itself when an operation is applied to it. Pea, 1986

Threshold concepts

Immutability as a gateway

Some ideas, once understood, transform how a learner sees what follows. Immutability plausibly works this way: until it clicks, assignment and memory never quite make sense. Boustedt et al., 2007

Cognitive load

Three things at once

Slicing asks a learner to hold the original string, the index positions and the resulting substring in mind simultaneously, which is a heavy load for a novice tracing code. Vainio & Sajaniemi, 2007

What this meant for the design

Make the model visible, not just the answer. Show which characters an operation touches, label what is included and what is excluded, and respond to a wrong answer by naming the belief that produced it.

2Try it yourself

Five questions our participants answered

These are the applied questions from the first-year evaluation cycle. Answer them before reading on. Each answer shows the kind of misconception-targeted feedback String Conundrum gives, and how our participants did. Nothing you choose leaves your browser.

0What does this print?
word = "Python"
print(word[1])

Indexing starts at 0, not 1: word[0] is P, so word[1] is y. This is the misconception indexing_from_one.

Indices start at 0, so index 1 is the second character.

Index 1 exists: the valid indices for "Python" run from 0 to 5 (or −6 to −1).

In our study, 33 of 35 participants answered the indexing item correctly.

Show the answer

Answer: y. Counting starts at 0, so index 1 is the second character.

In our study, 33 of 35 participants answered the indexing item correctly.

1What does this print?
word = "Python"
print(word[1:4])

Close, but the stop bound is excluded: word[1:4] takes indices 1, 2 and 3. This is slice_stop_inclusive, the inclusive-stop model.

The slice starts at index 1 (included) and stops before index 4 (excluded).

That counts from 1. Python counts from 0, so index 1 is y.

In our study, 30 of 35 answered correctly, and every one of the five wrong answers was ytho.

Show the answer

Answer: yth. Start at index 1 (included), stop before index 4 (excluded).

In our study, 30 of 35 answered correctly, and every one of the five wrong answers was ytho.

2What happens when this runs?
word = "Python"
word[0] = "J"
print(word)

Strings are immutable, so Python refuses to change a character in place. This is immutability_in_place, the most persistent model in our data.

Python stops with TypeError: 'str' object does not support item assignment. To change it, build a new string: word = "J" + word[1:].

The string does stay unchanged, but Python does not stay silent: it raises TypeError. This “silent no-op” model was not in the original catalogue and needs its own feedback.

An error is right, but not this one: index 0 exists. Python raises TypeError because a string's characters cannot be assigned at all.

In our study, only 24 of 35 recognised that the assignment is rejected: 7 chose Jython, 3 expected nothing to happen and 1 expected an IndexError.

Show the answer

Answer: it raises TypeError, because strings are immutable.

In our study, only 24 of 35 recognised that the assignment is rejected: 7 chose Jython, 3 expected nothing to happen and 1 expected an IndexError.

3What does this print?
text = "hello"
print(text.upper())
print(text)

upper() returns a new string and leaves text alone. This is method_mutates_target.

upper() returns a new string; the original is unchanged.

The first print shows the upper-case copy that upper() returns.

In our study, 11 of 13 participants in the first-year cycle answered correctly. This item was added in Cycle 3.

Show the answer

Answer: HELLO then hello.

In our study, 11 of 13 participants in the first-year cycle answered correctly. This item was added in Cycle 3.

4What does this print?
first = "hello"
second = "Hello"
print(first == second)

== compares characters exactly, and h and H are different characters. This is comparison_ignores_case.

String comparison is case-sensitive, so the two strings differ.

Comparing two strings with == is always allowed; it returns True or False.

In our study, 32 of 35 participants answered correctly.

Show the answer

Answer: False. Comparison is case-sensitive.

3Language

Language as a compounding barrier

Programming is mostly taught in English, including to many learners for whom English is not a first language. A survey of 840 learners in 86 countries found barriers in reading instructional material and in learning English and programming at the same time Guo, 2018. In a stronger causal design, novices using Scratch in their home language learned new concepts faster than peers using the English interface Dasgupta & Hill, 2017.

Most localised tools translate the language a learner writes, its keywords, rather than the teaching around it Swidan & Hermans, 2023. At UCT the question is not abstract: the Language Policy adopted by Council in December 2024 recognises isiXhosa as an official university language and commits to resourcing it for teaching and assessment University of Cape Town, 2024.

What this meant for the design

Localise the teaching (lessons, prompts, hints and feedback) and let learners write keywords in isiXhosa, but keep the program that actually runs in standard Python, so there is only one language whose behaviour has to be correct.

4Related work

The gap in existing tools

Each family of tools solves part of the problem. Visualisers make execution visible but leave the learner to interpret it. Misconception tutors target general language semantics rather than strings. Localised languages translate keywords rather than teaching.

A systematic review of seven online coding tutorial systems found none that addressed string-specific difficulties Alasmari et al., 2023. Static analysis can detect some string-comparison errors, but not explain why they are wrong.

Among the tools reviewed, none combines string-specific visualisation, misconception-aware practice and pedagogical localisation, and none is organised around a catalogue of string misconceptions. That is a design gap rather than a missing feature, and it is the gap String Conundrum was built to fill.

5Design input

The misconception catalogue

Twenty-four entries compiled from the literature, the CSC1015F curriculum, consultation with the project supervisor and locally observed tutoring experience. Each entry had to justify a concrete interface or feedback decision. Four slicing entries record concepts the interface must teach, rather than misconceptions.

slice_stop_inclusive

The visualiser labels the start included and the stop excluded, and draws the stop cell outside the selection.

negative_index_confusion

Positive and negative indices are always shown together, as a second row of numbers rather than a footnote.

count_vs_find_confusion

Feedback names the misconception behind a wrong answer instead of only marking it wrong.

Fundamentals and concatenation6

  • strings_need_quotesUnquoted text is a string valueSource: Kohn, 2019
  • string_vs_list_confusionBracketed characters form a stringSource: local tutoring
  • escape_sequence_literal_confusion\n is two literal charactersSource: curriculum
  • concatenation_adds_space+ inserts a separatorSource: local tutoring
  • concatenation_requires_same_type_fearStrings must match in kind to joinSource: Qian & Lehman, 2017
  • repetition_confused_with_multiplication* performs arithmeticSource: Qian & Lehman, 2017

Indexing3

  • indexing_from_oneThe first character is at index 1Source: Izu & Weerasinghe, 2020; curriculum
  • negative_index_confusionNegative indices are invalid or count forwardSource: local tutoring
  • off_by_one_lengthlen(s) is a valid indexSource: Vainio & Sajaniemi, 2007; local tutoring

Comparison and formatting4

  • comparison_ignores_case== is case-insensitiveSource: Altadmri & Brown, 2015; Blok & Fehnker, 2017
  • strings_not_orderable_mythStrings cannot be orderedSource: local tutoring
  • string_number_equality_myth'10' == 10Source: Qian & Lehman, 2017
  • fstring_missing_prefix_effectBraces substitute without the f prefixSource: Hughes et al., 2010

Slicing6

  • slice_stop_inclusiveThe stop bound is includedSource: Luxton-Reilly & Petersen, 2017; local tutoring
  • negative_step_unfamiliarA negative step is an errorSource: local tutoring
  • slice_defaults (concept)An omitted bound falls back to its defaultSource: curriculum
  • slice_step (concept)Step selects within the slice rather than moving the boundsSource: curriculum
  • slice_clamping (concept)Slice bounds clamp; indexing does notSource: curriculum
  • slice_empty_result (concept)A slice that cannot advance returns emptySource: curriculum

Immutability and methods5

  • immutability_in_placeOperations modify the original stringSource: Lu & Krishnamurthi, 2024
  • method_mutates_targetMethods change the variableSource: Lu & Krishnamurthi, 2024; Izu & Weerasinghe, 2020
  • strip_only_removes_one_charstrip() removes a single characterSource: local tutoring
